# Changelog

Contract changes after Day 1 need Tech Lead approval and an entry here.

## `responsive` deterministic check — 10 Nov 2026
- **Contract change (additive), migration `0008`:** `deterministic_checks.check_type` and the API `CheckType` gain `responsive`. `run_checks` now also runs `check_responsive` (advisory, `must_pass=False`): it flags an agent reply that repeats an earlier line of its own in answer to a caller question. Advisory checks never fail a call or change its verdict; the result is shown in the web call detail as "Responds to questions" and is included in the judge prompt's deterministic-checks list.

## Per-project LLM settings + test designer chat — 6 Nov 2026
- **Contract change (additive), migration `0003`:** new table `llm_settings` (one row per project, overrides the environment). New routes `GET|PUT|DELETE /settings/llm` (GET: read key; PUT/DELETE: admin) and `POST /settings/llm/test` (admin). Providers `deepseek` (default), `gemini`, `openai_compatible` (the DeepSeek client on a user `base_url`; https, SSRF-checked unless `PAREEKSHA_DEV_ALLOW_PRIVATE_TARGETS=1`; it never receives the environment's DeepSeek key). The API key is write-only (Fernet with `SECRET_KEY`; the API shows `api_key_set` and the last four characters). Judge, caller, scenario generation, role detection and the designer use the project's settings; the simulator, evaluator, auditor and generator workers pick up a change on the next message (provider cached by project + settings fingerprint). The dialect worker stays environment-only. New `LLMPurpose.DESIGNER`, `*_DESIGNER_MODEL` (default: the judge model), `DESIGNER_TEMPERATURE` (0.2).
- **Contract change (additive):** `POST /designer/chat` (stateless test designer assistant, prompt `designer_v1`) and `POST /designer/commit` (agent + scenarios + new personas in one transaction; returns the run wizard link). SDK: `designer_chat`, `designer_commit`, `get_llm_settings`, `update_llm_settings`, `test_llm_settings`.

## Report tool calls after the call — 6 Nov 2026
- **Contract change (additive):** new `PUT /calls/{id}/tool-calls` (write key; body `{tool_calls: [{name, arguments?, result?, at_ms?}]}`, max 200) replaces the call's tool trace and marks `calls.metadata.tool_trace = "reported"`; `409` for a glass-box simulated call, completed calls are re-evaluated. `POST /webhooks/inbound/{id}` gained an optional `tool_calls` field (same items). The evaluator loads the table trace for any call marked `reported`; calls without a trace keep "unknown" tool checks. SDK: `report_tool_calls(call_id, tool_calls)`. No migration.

## Tenant-scope ops surfaces + ingest resource limits (SEC-01) — 5 Nov 2026
- **Contract change (additive, security): two new nullable columns.** `api_usage.project_id uuid REFERENCES projects(id) ON DELETE CASCADE` and `dead_letters.project_id uuid REFERENCES projects(id) ON DELETE CASCADE`, each with an index (`api_usage_project`, `dead_letters_project`). Updated in lockstep in `docs/schema.sql`, its byte-identical copy `backend/alembic/sql/0001_initial.sql`, and the SQLAlchemy models (per contract 6.5). Columns are nullable and populated best-effort at write time, so existing rows and the fixed migration need no data backfill.
- **Security fix — cross-tenant isolation.** `GET /usage`, `GET /metrics/summary` (its `dlq_open` and `credits_used`) and the run/regression budget guard now aggregate `api_usage` scoped to the caller's `project_id` (previously a deployment-global sum readable by any `read` key, and a budget gate computed from every tenant's spend). `GET /dlq` and `POST /dlq/{id}/replay|discard` now scope to the caller's `project_id` (previously any `read`/`admin` key could read, replay or discard every tenant's dead letters). `metrics.usage`/`metrics_summary`/`_credits_used`, `runs.service._spent`, `regression.estimate.remaining_budget`, and `ops.dlq.list_dead_letters`/`replay`/`discard` gained a `project_id` parameter; usage is attributed at every `api_usage` insert site (LLM `UsageScope`, audit/dialect/generator inserts) and the DLQ recorder resolves `project_id` best-effort from the stored envelope's ids.
- **Security fix — ingest resource limits.** `POST /audits` decode now rejects recordings longer than `MAX_DURATION_S` (1800 s) or with more than 2 channels using an `sf.info()` header preflight *before* the full PCM decode allocates, bounding a decompression-bomb upload. The `audio_v1` adapter now uses a bounded event queue (backpressure) and a per-call frame/byte budget (`MAX_TOTAL_FRAMES`, `MAX_TOTAL_BYTES`), so an untrusted agent-under-test peer cannot exhaust a shared simulator worker by flooding frames.

## Inbound webhook source (INT-03) — 27 Oct 2026
- `POST /webhooks/inbound/{integration_id}` is real (the `STUB(INT-03)` handler). Shapes and status codes as documented (202/400/401/404/408/422); extra error codes `timestamp_out_of_window` (408), `unsafe_url` and `unknown_agent` (422). Additive: the built-in `webhook` connector now reports `direction: "both"` (it implements `ingest`; it was `"sink"` while only the sink existed) and its config gained optional `default_agent_id` (agent used when the payload's `agent_name` matches none). The frozen `Connector` interface is unchanged.
- `PAREEKSHA_DEV_ALLOW_PRIVATE_TARGETS=1` now also lets the import path (inbound URL check and recording download) reach a loopback host; unchanged otherwise.

## Evaluator and finalizer workers (EVAL-03b) — 24 Oct 2026
- Additive behaviour, no contract change: `run.completed` is emitted once per run with id `uuid5(run_id, "run.completed")` by the finalizer consumer or its every-minute completion reconciler (whichever wins the atomic claim), also for runs the API cancelled (status stays `cancelled`; only `summary` and `finished_at` are filled). `Outgoing` (consumer framework) gained an optional `event_id`. `run_items` move `completed -> evaluating` while the judge runs. See `docs/contracts.md` section 1.
## Audit pipeline (EVAL-04) — 24 Oct 2026
- **Contract change (additive, needs TL/owner approval, raised as an ISSUE by EVAL-04):** `STTProvider.transcribe(..., denoise: bool = False)` and `STTCapabilities.denoise` (default `False`). Gnani passes it to the batch job (`denoise=True`); google, azure, elevenlabs and deepgram raise `UnsupportedCapabilityError` when it is requested (the TRD requires "diarize, denoise" for audits). Existing callers are unaffected.
- `POST /audits` and `POST /calls/{id}/speaker-map` are real (the two `STUB(EVAL-04)` handlers). No change to their documented request/response shapes; speaker-map answers `400` for unknown or incomplete roles and `409` when the call is not an uploaded/imported, completed call.
- New runtime pieces (no frozen contract touched): `pareeksha/audit/` (ingest, turns, role detection, pipeline), `pareeksha/storage/blob.py` (`BlobStore`, `DATA_DIR`), prompt `role_detect_v1.j2`, workers `auditor` and `evaluator` (the latter with the Postgres store `evaluation/store.py`, so audits and simulations share one code path), `events/outbox.enqueue_session`. `soundfile` is now a declared backend dependency (WAV/MP3 decode).
