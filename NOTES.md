- FE-01: API spec says base `/api/v1`; if TL-01's OpenAPI paths include that prefix, the generated client paths will too, so `PAREEKSHA_API_URL` (already ending in /api/v1) would double it. Decide when wiring real client. (web/lib/api/client.ts)
- EVAL-02: Python `\w` and `str.isalnum` do not match Indic combining vowel signs, so regex word tokenisation splits Kannada/Hindi words; tokenise on whitespace and strip punctuation (backend/pareeksha/evaluation/numbers.py).
- EVAL-02: NFC decomposes Devanagari ज़/ढ़ into base + nukta (U+093C); numeral/WER normalisation strips nukta and maps chandrabindu to anusvara so हज़ार==हजार, पाँच==पांच (numbers.py `_norm_word`).
- INFRA-01: apache/kafka:4.0.0 + KRaft compose works unchanged from starter; kafka-init is idempotent. Behind a TLS-intercepting proxy `pip` inside `docker build` fails SSL; use `docker-compose.proxy.yml` (CA as build secret) rather than disabling verification. See proof/INFRA-01/proof.md.
- INFRA-01: worker services need compose profile `workers` until their modules exist (INFRA-02+), else crash-loop. See docker-compose.yml.
- TL-01: DeepSeek API (api-docs.deepseek.com, checked 2026-10-23): model IDs `deepseek-flash` and `deepseek-v4-pro` (legacy `deepseek-v4-flash` still accepted); JSON mode is `response_format={"type":"json_object"}` only (no server-side JSON Schema; prompt must contain "json" plus an example; content may be empty occasionally, so treat as retryable). Thinking mode is on by default and IGNORES `temperature`; disable with `extra_body={"thinking":{"type":"disabled"}}` for the judge. Prices per 1M tokens (peak, cache miss): flash $0.30 in / $1.20 out, v4-pro $1.32 in / $3.96 out; off-peak half. Pages: /quick_start/pricing, /guides/json_mode, /guides/thinking_mode. Contract: backend/pareeksha/llm/base.py.
- TL-01: FastAPI 0.161 no longer exposes flattened `app.routes` (it returns lazy `_IncludedRouter` objects); tests iterate `pareeksha.api.main.ROUTERS` instead (backend/tests/contract/test_stub_routes.py).
- TL-01: pydantic wraps `ValueError` subclasses raised inside validators into `ValidationError`, so `parse_envelope` pre-checks the event type to raise `UnknownEventTypeError` (backend/pareeksha/events/schemas.py).
- VOICE-02: LineSimulator re-blocks input into fixed 20 ms frames, so chunked==whole is bit-exact; streaming SNR uses a causal speech-power estimate unless `speech_power`/`noise_power` are given (`LineSimulator.simulate` does a two-pass exact calibration). Noise beds are procedural (no licensed clips); band-pass IIR leaves ~1.4 ms group delay (resamplers are delay-compensated). See `proof/VOICE-02/proof.md`.
- QA-01: test plan is docs/TEST_PLAN.md; the coverage script parses its section 2 table, so keep the 8-column row format when editing ([plan](docs/TEST_PLAN.md)).
- VOICE-01: Gnani verified against SDK source + docs (https://docs.gnani.ai/api/STT/stt-websocket, https://docs.gnani.ai/api/TTS/tts-sse). - VOICE-01: Timbre v3.0 TTS WAV has 0xFFFFFFFF RIFF/data sizes (streaming header): `wave` reports ~134,000 s. `pareeksha.gnani.normalize_wav` rewrites it; always use it before measuring or mixing TTS audio.
- VOICE-01: Verbatim STT spells acronyms ("ಇ ಎಮ್ ಐ", "ई एम आई") so TTS->STT WER is 0.30-0.40 on a 10-word phrase even when every word is audible; WER-based checks need acronym-spacing normalisation. Kn voices Lakshmi/Avinash and Hi voices Shivani/Shubham all round-trip (judged by STT output only, not by ear; no human listened). Chosen: kn Lakshmi (caller)/Avinash (agent), hi Shivani/Shubham.
